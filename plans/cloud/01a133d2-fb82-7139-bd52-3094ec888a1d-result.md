## Summary

The published `views/search.pug` now gives `input.search__input` an
`aria-label` from `t('search_label')`, falling back to `Search` when `t` is
absent, returns the key, or returns an empty/non-string value.
`h1.search__title` is wrapped in `if !(app && app.searchShowTitle === false)`.
`index.js` reads a new opt-out key `show_title` (only an explicit `false`
turns it off) and returns it as `app.searchShowTitle`; the index files are
unchanged. Documented in `config/search.yaml` and the README; 11 new tests.
Semver: minor (2.3.0) — no version bump or CHANGELOG edit on the branch.

## Decisions

- **Branch**: the cloud session was started on the harness branch
  `claude/search-template-a11y-x4ifb0`; the work was done on
  `issue/01a133d2-search-template-a11y` (from `main`) as the brief asks, and the
  same commits are pushed to both branch names.
- **Label fallback** also covers a non-string or whitespace-only `t()` result,
  not only `''` and the key — cheap, and never emits `aria-label="  "` or
  `aria-label="1"` from an odd translation value.
- **Label computed at the top of the template** (unbuffered `- var searchLabel`)
  outside `.section.search`, so the wrapper markup stays untouched. A site that
  includes the template shares Pug scope, so a site variable named
  `searchLabel` would be overwritten — unlikely, accepted.
- **Condition is `if !(app && app.searchShowTitle === false)`** rather than
  `if app.searchShowTitle !== false`, so rendering with no `app` (existing
  tests, custom hosts) does not throw.
- **`h1` text stays the literal `Search`** (not routed through `t()`), as the
  brief says not to change the element, class or text.
- **No `getMetaData` change**: `show_title` is site-wide, so it lives on `app`
  only.
- **README**: the Usage step 3 example (Markdown without a heading) stays as
  the default story; the new "Heading and label" subsection shows the
  `show_title: false` + `# Search` variant.
- **Tests**: added an extra "index byte-identical with show_title: false" hook
  test and an "other input attributes unchanged" template test beyond the brief's list.

## [2.3.0] - 2026-10-13

### Added

-   `show_title` in `config/search.yaml` (default `true`), exposed as
    `app.searchShowTitle`. Set it to `false` and the shipped `search.pug`
    leaves out its `h1.search__title`, for a search page that brings its own
    `h1` (e.g. a `# Search` heading in the Markdown) — `nera build --check`
    then finds one `h1` instead of warning `a11y-h1`. Without the key the
    markup is unchanged.

### Fixed

-   The shipped `search.pug` gives its search input an accessible name:
    `aria-label` from the site's `t('search_label')`, falling back to
    `Search`. `nera build --check` no longer warns `a11y-form-label` for it.
    Translate it with a `search_label` key in the site's translations.
-   `npx nera-search` skips an existing vendor folder, so a site that
    published the template before keeps its old copy. Refresh it with
    `npx nera-search --force` only if you never edited it; otherwise add the
    `aria-label` and the `if` around the `h1` by hand (see the README's
    Template Publishing section).
